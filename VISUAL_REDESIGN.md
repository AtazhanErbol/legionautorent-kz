# Тёмный редизайн: план и границы

База до изменений: 6c3284b. Данные, импорт, Admin, формы и файл frontend/hero.js сохраняются. Новые референсы пользователя в design_refs/ui/ не перезаписываются.

Палитра: #000000 фон, #111111 поверхность (тон чёрного), #1F1F1F карточки, #FFFFFF текст, #F7B500 акцент, #ffdd56 hover. Серые подписи и линии получаются прозрачностью белого. Exo 2 — крупные заголовки/цены, Golos Text — текст и управление; существующие self-hosted файлы с KK-глифами.

Контейнер 1280 px, шаг 8 px, секции 96/56 px. Текст слева. Главный визуальный акцент — большой автомобиль; остальные блоки спокойные. Жёлтый только в действиях, ценах и небольших маркерах, без жёлтых/белых заливок целых секций.

```
прозрачный header → сплошной при прокрутке
H1 и три числа         крупная 3D-сцена
        город | даты | категория | найти

                    показать ещё
```

Из SIXT — единая панель поиска, из Turo — иерархия фото/названия/стоимости, из OneClickDrive — компактные действия связи в карточке. Светлые фоны референсов не копируются: направление пользователя требует единого тёмного сайта. 3D-референсы используются как ориентир освещения и композиции; временная GLB остаётся прежней.

Каталог целиком в SSR, JS показывает первые 12, затем раскрывает остальные без запросов; без JS доступен весь список. Категории — из CMS. Для каталога адаптируется представление результата, но сами фильтры/данные не меняются. H1/Title/description/canonical/SEO-тексты остаются исходными. Два согласованных SEO-изменения: og:url городов и только полные опубликованные hreflang.

Проверка: не более трёх визуальных раундов, 1440 и 390 px (главная, город, автомобиль), отдельные кадры hero/карточки; ручная инспекция изображений и измерение перехода pin→каталог в живом браузере. Затем весь Django suite, 122 URL, mobile + desktop Lighthouse с включённой desktop-сценой. Базовые mobile Performance: 98/99/99.


## Результат и три визуальных прохода

1. Тёмная система общих шаблонов, карточки 16:10, панель поиска, timeline и SVG-иконки. В живом Chromium проверен pin: видимого разрыва перед каталогом нет. Найдены обрезанная на телефоне машина, частично скрытая панель поиска на desktop, лишняя высота пустых характеристик и переполнение длинного H1 политики.
2. Исправлены кадрирование мобильного постера, высота desktop-композиции и пустые chips. Длинный H1 переносится. Lighthouse mobile 99/99/99/99; аудит выявил маленькие языковые ссылки и пропущенный H2 у списка каталога.
3. Языки перенесены в мобильное меню с зонами нажатия 56×48, кнопка меню 44×44. Добавлен скрытый H2 списка без изменения H1. Финальные шесть кадров: home/city/car в 1440×1000 и 390×844, плюс крупные hero/card и снимки остальных секций. Ошибок JS и горизонтального переполнения нет. Контрольные ширины: 320, 390, 768, 1024, 1440, 1920.

Каталог: все 91 машины в SSR без JS; главная содержит 59, Костанай 14. На старте показаны 12. Проверены раскрытие без запроса списка, классы из CMS, сортировка, AJAX расширенных фильтров, галерея и мобильное меню. Даты поиска передаются в WhatsApp; наличие по датам по-прежнему подтверждает менеджер. Пустые реальные характеристики не заменяются выдуманными.

В завершение третьего прохода галерея переключена на существующие AVIF/WebP с тем же центрированным кадрированием 16:10, без изменения оригиналов и записей БД. Итоговые кадры автомобиля обновлены и просмотрены: композиция сохранена. Мобильная скорость карточки — 99 во всех трёх контрольных запусках вместо 98/98/99 до этой оптимизации.

Существующий `frontend/hero.js`, GLB, имена узлов и маршруты не менялись. В текущем GLB остаётся упрощённый автомобиль; CSS-композиция не превращает его в фотореалистичную модель из 3D-референсов. Отражение и свет сохранены из сцены. Интерактивная карта загружается по нажатию, чтобы не замедлять первый экран.

`output/playwright/visual-round-3/` — итоговые PNG и report.json; `reports/visual_redesign_check.json` — проверка. Полностраничные PNG принудительно рисуют content-visibility карточек только на время снимка; поведение реальной страницы измерялось отдельно. Главный full-page кадр может отображать техническую область pin-spacer: в реальном viewport её закрывает закреплённая сцена, что проверено на шести точках scroll. Для оценки первого экрана служит home-1440.png, перехода — hero-scroll-740.png и hero-scroll-1100.png.
