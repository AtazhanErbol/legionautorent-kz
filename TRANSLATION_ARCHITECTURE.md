# RU / KZ / EN: архитектура

Дополнение ТЗ от 2026-10-02 имеет приоритет. Старый сайт содержит только RU; его URL и непустой контент сохраняются.

| Язык | URL | HTML lang / hreflang |
|---|---|---|
| RU | существующий URL без prefix | ru |
| KZ | /kz + существующий URL | kk |
| EN | /en + существующий URL | en |

LocaleMiddleware активирует стандартный Django gettext по пути. Сессия, browser language и cookies не перенаправляют поисковых роботов с русского URL. Переключатель всегда ведёт на соответствующий путь, включая slug и slash.

Русские поля моделей — исходный слой RU. Переводы хранятся в нормализованной seo.Translation, уникальной по (тип объекта, id объекта, language). Это соответствует title_ru/kk/en, description_ru/kk/en, h1_ru/kk/en и content_ru/kk/en без размножения одних и тех же столбцов в каждой модели. Admin: основной RU fieldset, отдельные раскрываемые KZ/EN inline sections с language selector и флажком публикации. Для городов, автомобилей, категорий, FAQ, страниц, преимуществ, шагов, условий и SiteSettings доступны отдельные переводы.

SEO-страница может быть опубликована только с Title, Description, H1 и content. Пустой/непроверенный перевод получает notice, noindex,follow, canonical русского оригинала; исключается из sitemap и альтернатив. Полный опубликованный перевод получает self canonical и взаимные hreflang ru/kk/en + x-default RU. Нельзя ставить hreflang=kz. Каталог переводов индексируется после заполнения всех публичных машин, городов и категорий; UI без контентных переводов сам по себе не открывает индексацию.

Партнёры: SiteSettings.show_partner_section, partner_title, partner_description, partner_phone, partner_whatsapp, partner_whatsapp_message; отдельные поля партнёрского контента и сообщения в KZ/EN Translation. В RU используются ровно заданные пользователем тексты. При пустом переводе блок скрывается на соответствующем языке до публикации. Номер берётся из настроек, пустое override использует основной телефон/WhatsApp. Никаких инвестиционных заявок, форм, таблиц и статусов.

144 интерфейсных строки вручную заданы в locale/ui_translations.json и скомпилированы в стандартные django.po/mo. Динамического машинного перевода нет. Исходные автомобили/города автоматически не переводятся. После редакторской проверки переводы можно публиковать из Admin без разработчика.

`python tools/build_messages.py` собирает .po/.mo и проверяет покрытие статических UI-строк. Для этого требуются requirements-dev.txt. Содержимое .mo сохранено в проекте и production не требует gettext compiler.
